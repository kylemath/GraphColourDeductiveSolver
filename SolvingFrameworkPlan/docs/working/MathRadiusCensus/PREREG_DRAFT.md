## What this is and how it differs from Long Table's WP22/S2
S2a is a hill-climb over graphs of minimum degree >= 4 (orders 12 to 30), S2b a census of the symmetric families A_r (degrees 5 and 6 only). **This census is exhaustive over a different set: every plane triangulation with minimum degree 5 (separating triangles allowed, flagged) of order 12 to 24, every degree-5 vertex as hole, every doubly locked (DL) state.** It uses neither S2's search nor its seeds, and does not touch A_r beyond regression checks. DL, filled, radius are as in `MathConfinementAttack` Step 1 and `MathConjectureR` section 1 (r(s) = least number of whole-component Kempe swaps of T-v to a filled state, link uses <= 3 colours).

## Statements (fixed before any run)
- **S-R (finite radius):** every DL state at every degree-5 hole of every graph in the set has finite Kempe radius (no targetless class).
- **Reports (descriptive, never evidence for R):** per order the number of graphs, holes, canonical colourings, DL states; **maximum DL radius per order**, the histogram of DL radius over all DL states, split 4-connected / with separating triangle; a witness (graph, hole, colouring) of each maximum. No numerical prediction for the maximum is registered; the known value is radius 4 (T4, order 17, MathConjectureR), so the order-17 row must contain radius 4, or the tool is wrong.
- **KILL-3 (targetless class):** a hole record with `unreached > 0`, i.e. some Kempe class of canonical colourings of T-v containing no filled state. The class is complete by construction (the program lists all canonical colourings of T-v and all swaps). A KILL-3 record is not announced until (i) `verify_census.py` recomputes it by its own code (partition-based, different method), and (ii) the graph is rechecked against the project's protected-face definitions (this census has no protected face, so a KILL-3 is a statement about R in the setting without phi, not about a core component).
- **Capped** (`capped:true`, more canonical colourings than the cap) is inconclusive, never a kill or a pass. Not claimed: anything about orders > 24, about minimum degree 4 (S2a covers), about states with a protected face meeting N[v], or any change of a status word. A pass (no KILL-3) is a statement about these graphs only.

## Tools (all in `docs/working/MathRadiusCensus/`)
`gen_tri.cpp` (generator) / `census.cpp` (per hole: all canonical 4-colourings of T-v by DFS with first-appearance renaming, classify, Kempe graph by all whole-component swaps of all six pairs, multi-source BFS from filled, output JSONL) / `run_census.py` (stages generator shards -> merge+dedup -> census blocks; every file written to `.part` and renamed on exit 0; `manifest.json` rewritten atomically; re-run skips finished shards; 3 retries; `--report` says PARTIAL or COMPLETE and exits 3 on a KILL flag) / `verify_census.py` (written from its docstring spec only; imports nothing from the other files; states are partitions) / `tests.py`.
Build: `g++ -O2 -o gen_tri gen_tri.cpp; g++ -O2 -o census census.cpp`. Run: `python3 run_census.py N --gen-parts K --block B --workers W`.
