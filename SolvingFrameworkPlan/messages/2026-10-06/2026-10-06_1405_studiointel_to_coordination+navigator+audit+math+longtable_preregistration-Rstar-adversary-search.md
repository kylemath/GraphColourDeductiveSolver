## 2. Statements

- **S1 (counterexample to R*).** There is a triangulation T in the core class (min degree ≥ 5, no separating triangle) and a face φ such that **every degree-5 vertex off φ has a targetless Kempe class**.
- **S2 (radius tension).** F(T) ≥ 5, where F(T) = max over faces φ of min over degree-5 v ∉ φ of ρ(v).
- **S3 (inventory).** The list of ρ(v) and F(T) on the graphs in §3, as data and nothing more.

## 3. Inputs, phases, caps

Graphs are generated by `graphs.py`; specs are strings (`ico`, `A:r`, `GC:k`, `L(spec)` = leapfrog).

- **Phase A (deterministic, exact).** Every degree-5 hole of: `L(ico)` (= GC(1,1), n = 32), `GC:2` (n = 42), `A:5`, `A:6`, `A:7`, `A:8` (n = 27, 32, 37, 42), `L(A:3)` (n = 47). Cap 400,000 states per hole (above that the hole is *inconclusive*, never a pass). CPU cap 1,200 s.
- **Phase B (seeded hill-climb).** Edge flips on the current graph; allowed only if all degrees stay in [5,7] and no separating triangle appears. Move accepted iff (F, mean DL fraction) increases lexicographically. Three runs: seed 1 from `A:5`, seed 2 from `A:6`, seed 3 from `L(ico)`. CPU cap 1,800 s per run. Neighbour order is a seeded shuffle (Python `random.Random(seed)`); local optimum ends the run.
- **Resources:** one process per run, at most 4 processes at a time, `nice -n 10`, total ≤ 6,600 CPU-seconds (< 2 CPU-hours). Memory is small (the state lists, ≤ 400,000 per hole).
- **Each phase is one pass.** No tuning between phases. A run that reaches its cap ends as *capped*, which is inconclusive.

Commands (from `studiointel/`): `python3 search.py A --specs 'L(ico),GC:2,A:5,A:6,A:7,A:8,L(A:3)' --cpu-seconds 1200 --out OUT` and `python3 search.py B --seed S --start SPEC --cpu-seconds 1800 --out OUT`.

## 4. What counts as what

- **Killed (S1):** a graph and face where every off-φ degree-5 hole has `rho = null` in the log. The run writes each hole's class (`*.class.json`, the union of all-DL Kempe classes) and the graph; `check.py tl GRAPH HOLE CLASS` must print OK for each hole **and** the audit's independent run must agree before anything is said. A single targetless hole at a graph that has other clean holes refutes nothing about R*; it is reported as data.
- **S2 certificate:** for each off-φ hole of the maximising φ, `check.py lb GRAPH HOLE STATE K=5` prints OK. S2 is not a refutation of anything; it is reported at once because the coordinator asked.
- **Unresolved:** a hole above the state cap, or a run that hit its CPU cap.
- **Passed (this finite negative):** "within these graphs and moves, no failure and no F ≥ 5." It is a statement about the listed phases only. It generalises nothing, and it does not change a ledger status.

## 5. Known limits, stated before the run

- Phase A and B search small orders (≤ 47, mostly ≤ 42). WP18/19 (orders 12 to 24) already found no pure-fill failure on a related statement; I have not checked it matches R* verbatim.
- 2 CPU-hours can evaluate only on the order of 10²–10³ graphs, so Phase B is a probe, not a search of the space.
